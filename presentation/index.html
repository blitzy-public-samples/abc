Welcome. This is a short, five-minute briefing on a new Node.js teaching service we added to the ABC repository. It is intentionally small and is fully isolated from the ABC EDA toolchain. I will cover what it is, what changed, why it matters, and the risk posture.

Context

  • A small, framework-based HTTP server added as a teaching and example artifact.
  • Built on Node.js, the standard server-side JavaScript runtime.
  • Self-contained in its own nodejs-tutorial/ directory.
  • Completely independent of the ABC EDA core — it shares no code or build path.
The goal here is education and demonstration, not production EDA work. It gives newcomers a minimal, modern HTTP service they can read end to end, and it never touches the C/C++ engine.

What Changed

We adopted the industry-standard Express.js framework (express@5.2.1) and exposed two GET endpoints.

UC Berkeley, ABC 1.01
abc 01> npm start
  Server listening on http://localhost:3000

GET /             → Hello world
GET /good-evening → Good evening
Two routes only. The root path returns Hello world; a second route returns Good evening. Express gives us clean, declarative routing, so adding more endpoints later is trivial.

Why It Matters

  • Maintainable routing — each endpoint is a clear, declarative one-liner.
  • Easy extensibility — new endpoints are added with minimal code.
  • Industry-standard framework — Express is widely adopted and well supported.
  • Lower cost — familiar tooling reduces onboarding and maintenance overhead.
The business value is speed and familiarity. Most engineers already know Express, so the learning curve is near zero and long-term maintenance stays inexpensive.

Risk & Isolation

  • New code is fully isolated from the C/C++ EDA toolchain.
  • It sits outside the Bazel / CMake / GNU-Make src/** discovery.
  • It is kept out of the git-ignored docs/ and build/ paths.
  • No impact on the existing build or CI.

Isolation Detail

  • Bazel — source globs are scoped to src/**; new directories are not matched.
  • CMake — discovery is rooted at src/; new directories are invisible to it.
  • GNU Make — modules are discovered under src/; nothing new is picked up.
  • The only repository touchpoint is a one-line .gitignore rule for node_modules/.
For the technically curious: each of the three build systems discovers sources only under src. The single shared change is ignoring node_modules so dependencies are never committed.
